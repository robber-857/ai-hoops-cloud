# 训练与饮食系统操作说明

> 2026-10-03 范围已调整：本说明保留的是 2026-10-01 本地功能操作记录，其中菜谱、全天能量和三餐比例不再属于当前主流程。新版本待按 [现行开发交接](holiday-camp-development-handoff-2026-10-03.md) 实施后更新操作说明；目前不能据本文宣称精简版或课程消耗已可用。下方环境和验证均按原日期理解。

更新：2026-10-01。本文说明当前本地功能；前端 http://127.0.0.1:3000，后端 8000。未部署生产。

## 1. 训练计划与实际课次

**Training plans（训练计划）**记录准备练什么；**Actual lessons（实际课次记录）**记录某一天真正上了什么课、每个人参加多久。Actual lessons 不是已完成课数，也不是视频评分。

教练从 `/coach/lessons` 进入，选择班级和已发布计划，建立课次。

| 界面字段 | 中文含义及填写方式 |
| --- | --- |
| Class | 班级，教练只能操作自己获授权的班级 |
| Published plan | 用来建立课次的已发布训练计划 |
| Lesson date | 实际上课日期，按 Australia/Sydney 归日，不是报告发布日期 |
| Actual minutes | 全班该项目实际进行的分钟数，不一定等于计划时长 |
| Participation | 某个学员实际参与情况，见下表 |
| Notes | 备注；课次备注描述整节课，个人备注只描述该学员 |
| Lesson version | 保存后的课次版本；用于区分修改记录，不是评分 |

| 参与状态 | 意义 |
| --- | --- |
| Unconfirmed | 尚未确认；不能发布整班报告 |
| Full attendance | 完整参加，个人各项目分钟数等于全班实际分钟数 |
| Absent | 缺席，个人分钟数为零，只生成出勤记录 |
| Left early | 提前离场，按项目先后顺序记录实际参加时长 |
| Partial participation | 部分参与；逐项填写个人时长，不能超过该项目实际时长 |

操作顺序：建立课次 → 填全班实际时长 → 确认每位学员出勤和个人时长 → **Save lesson record** → 预览个人记录 → **Publish saved class records**。

**保存不等于发布。** 保存是教练留存记录；发布后学员才能在 `/me/class-reports` 看到，并收到通知。修改后需要再次保存、预览、发布。旧发布版本保留；重复发布同一版本不会重复通知。

## 2. 学员课后报告与每日汇总

Class reports（课后报告）只展示登录学员自己的记录。个人参与分钟数用于说明训练事实，不表示热量消耗。身体资料采用发布时选取的、测量日期不晚于上课日期的记录；之后更新资料不改写旧报告。

从 Class reports 进入 **Daily summary（每日汇总）**，按上课日期查看：

| 字段 | 意义 |
| --- | --- |
| Published lessons | 当天已发布、包含本人的课次数，含缺席课次 |
| Attended lessons | 当天参与的课次数，含全勤、提前离场及部分参与 |
| Absent lessons | 当天缺席的课次数 |
| Participation minutes | 当天各课个人参与分钟数之和；每节课只取最新发布版本 |
| Report / Lesson v… | 汇总来源，可打开报告查看详情和历史 |

汇总会随新的发布更新；它不是单独发布的永久每日快照。仅保存未发布的修改不影响汇总。发布修订日期后，课次会从旧日期移到新日期。没有记录表示没有已发布数据，不代表当天没运动。分钟数是记录相加，不推断不同课次有无时间重叠。

热量计算、全天需求和三餐建议仍待完成。“经常运动、重点看热量”已记录为产品方向，但还没有定下具体公式和三餐比例；界面不会把未计算显示成 0 kcal。

## 3. 管理员如何编辑 Recipe（菜谱）

使用 Admin 账号进入 `/admin/recipes`，选择菜谱的编辑入口。`/recipes` 是已发布菜谱浏览页；教练和学员不能维护菜谱。

1. 打开已有菜谱，或新建菜谱。
2. 填菜名、份数、做法；搜索食材并点 Add 加入。
3. 填各食材的可食用克数；不要的食材点 Remove。
4. 点 **Save draft & preview** 保存草稿并检查营养换算。
5. 确认后点 **Publish saved version**，其他人才能看到这个版本。

| 字段 | 中文含义及示例 |
| --- | --- |
| Recipe name | 菜谱名称，例如“鸡蛋西兰花米饭” |
| Number of servings | 整道菜分成几份；总营养除以份数得到每份营养 |
| Finished weight in grams | 烹饪后整道菜的总重量，可选；不是单份重量 |
| Food source | 食品成分数据库及版本，用于追溯营养来源 |
| Food name | 数据库中的具体食品；应核对生熟状态、部位等 |
| Edible grams | 该食材实际可食用重量，必须与所选食品生熟状态一致。例如选熟米饭就填熟米饭重量 |
| Preparation note | 食材处理说明，例如“煮熟、沥干”；备注不会自动换算生熟重量 |
| Method / Instructions | 做法步骤 |
| Allergens | 过敏原清单，多个按界面提示用逗号分隔 |
| Allergens reviewed | 表示管理员已人工核对过敏原；不是系统自动检测结果 |
| Dietary notes | 饮食相关备注，不等于系统已验证适合每个人 |
| Image URL | 图片网址，可选，目前不是上传图片按钮 |

例如整道菜 600 kcal、分 2 份，每份为 300 kcal；这里只解释除以份数的含义，不是推荐热量。修改草稿不改变已发布页面，重新发布才会更新；历史发布内容保留。

## 4. 当前使用边界

菜谱营养换算已实现，但选一个菜谱不等于系统已生成个人三餐方案。实际饮食打卡不在当前首版范围内。当前演示菜谱明确标注 local demo；本地检查通过也不代表教练实际使用验收完成。

## 5. Admin 的 Energy reference（能量参考预览）

入口：管理员菜单 **Energy reference**，路径 `/admin/energy-reference`。

这个工具用于查看官方参考表与试算三餐分配。它用的是表中的参考体型，尚未按某位学员的身体资料计算个人需求。

| 字段 | 中文含义 |
| --- | --- |
| Age in completed years | 已满周岁，支持 4–18 岁；不是学龄或虚岁 |
| Sex used by the source table | 来源表使用的男/女分类，明确选择，不推断 |
| Whole-day activity (PAL) | 全天身体活动水平系数，不是这节课运动强度，也不是训练次数；必须选择，系统没有默认值 |
| Breakfast / Lunch / Dinner (%) | 本次试算的早/午/晚餐百分比；全部空白，或三个正数合计 100 |
| Source reference body | 来源表的参考体重和身高，不能当成该学员的测量值 |
| MJ / kJ / kcal | 能量单位；1 MJ = 1000 kJ。本工具按 1 kcal = 4.184 kJ 换算，并显示约数 |
| Reference version | 固定参考数据版本，用于追溯这次采用的依据 |

操作：选择年龄、性别、PAL → 可选填写三餐比例 → 点 **Preview reference**。修改任何输入后，旧结果会清除，需要重新试算；网络失败可以再次点击同一按钮。刷新不会保存本次输入。

三餐显示值相加等于全天显示值。比例由你输入，不代表官方建议；没有预设 30/40/30 或其他比例。这个页面不会向学员发布报告，也不会改菜谱或学员资料。全天参考已考虑所选活动情景，不要再把单课运动热量直接相加；晚上查看也不代表晚餐需要补吃全天量。

当前只试算热量分配，不生成碳水/蛋白质/脂肪克数。详见 [本轮范围与验证](holiday-camp-energy-reference-validation-2026-10-01.md)。

## 6. 教练的 Personal energy review（个人能量预览）

进入 `/coach/lessons` → 选班级 → Open lesson → 页面下方 **Personal energy review**。先保存课次，再选 **Activity scenario**，点 **Preview personal energy**。

| 字段 | 含义 |
| --- | --- |
| Activity scenario | 全天活动比较情景：Inactive 较少活动、Low active 较低活动、Active 活跃、Very active 很活跃。不是单节课强度，也不从参与分钟数自动判断 |
| Individual activity scenarios | 按学员分别选择本次全天活动情景；不选时使用班级比较情景。不是系统自动确认的个人活动等级 |
| Use class scenario | 这名学员使用上方班级比较情景；修改班级情景会影响使用此选项的人 |
| Clear individual selections | 清空全部个人选择，重新使用班级情景；之后需要重新预览 |
| About … kcal / day | 用本人身体资料和候选公式估算的全天能量，取约数；不是单课消耗 |
| Age … at … | 以实际上课日期计算的年龄 |
| Measured … days before | 使用哪一天的测量资料，以及它距上课多久；需要核实资料是否仍适合该学员 |
| Calculation details | 展开查看本次使用的公式和生长项；生长项已包含在结果中，不需另加 |
| Inputs: measurements frozen… | 本课已发布，使用发布时冻结的身体资料；新填的体重不会改写它 |
| Inputs: saved lesson… | 本课尚未发布，使用已保存课次及上课日期之前的资料 |

此处是候选规则审核预览，与 Admin 的澳新参考体型查询不同。选一个活动类别是比较情景，不表示全班活动水平都相同。缺资料会显示原因，缺席不生成该课预览；未知热量不会显示成零。现在可保存审核草稿，重新打开课次会恢复最近草稿的输入；尚未保存的输入刷新后不保留。草稿不向学员发布，也不会改变已发布课后报告。

本地可选 **Energy review class (local demo)** 演示班，直接检查完整资料、缺资料和缺席三种情况。详细来源及限制见 [个人能量验证](holiday-camp-personal-energy-validation-2026-10-01.md)。

若不同学员需要比较不同活动情景，在 **Individual activity scenarios** 按姓名选择。已经单独选择的人不受上方班级情景变化影响；每名学员结果会标出 **Individual review selection（个人审核选择）** 或 **Class comparison scenario（班级比较情景）**。个人选择随草稿保存，刷新或复用历史输入时恢复；旧草稿没有个人选择则使用其原班级情景。缺席者不提供个人选择，缺身体资料仍不生成数值。恢复旧草稿后若包含已移除或缺席的学员，先清空个人选择并核对当前名单。

### 个人三餐热量试算

Personal energy review 中新增 **Optional meal split for this review**：Breakfast / Lunch / Dinner (%) 分别是本次早/午/晚餐占全天热量的百分比。

三项都不填时只显示全天结果；要试算则全部填写正数，最多两位小数，合计必须为 100。点 **Preview personal energy** 后，每名资料完整的学员都会显示自己的三餐热量；缺席或缺资料者不分配。改比例后需重新预览。

各餐单位是 kcal，不是食材克数，也不是碳水/蛋白质/脂肪克数。三餐舍入后合计等于全天显示值。比例没有默认推荐，可随审核草稿保存，但不会正式发布；全天数值也不表示晚餐需要补吃的量。见 [测试记录](holiday-camp-personal-meals-validation-2026-10-01.md)。

### 保存与查看审核草稿

操作：保存课次 → 选择活动情景及可选三餐比例 → Preview personal energy → **Save energy review draft**。每次成功保存新增一个历史修订，不覆盖旧内容。

| 字段或按钮 | 含义 |
| --- | --- |
| Review draft r1 / r2 | 本课能量审核草稿的第 1 / 2 个修订，与课次版本分开计数 |
| Lesson v2 | 生成这份草稿时采用的已保存课次版本 |
| Pending review | 等待审核；保存并不表示规则已批准或学员已收到建议 |
| Use these review inputs | 把该历史草稿的活动情景和比例放回输入框；需要重新预览才能得到当前结果，不改写历史 |
| Retry same draft save | 网络失败后重试刚才那次保存；同一请求不会产生重复修订 |
| Reload draft history | 重新读取服务器历史，用于核对保存结果或处理版本冲突 |

展开历史可查看当时的身体资料、计算结果、三餐比例和规则来源。后来更改资料不会改写这些快照；课次版本改变时会提示旧草稿来自较早课次版本。刷新后恢复的是最近草稿的输入，若要按当前资料计算，需要再次点击预览。

保存前若课次、身体资料或预览结果已变化，系统会要求重新预览；其他操作产生新草稿时，需要重新读取历史后再保存。网络保存结果不明确时，输入暂时锁定，可重试同一保存或重新读取历史。

草稿只供有权限的工作人员审核，学员无法读取，也不会收到草稿通知。它按课次保存，并不是正式的每日营养报告。见 [草稿验证记录](holiday-camp-energy-drafts-validation-2026-10-01.md)。
