# P6a 课后记录发布与本地端口验收（2026-09-30）

本轮完成 **不依赖营养公式的课后记录发布流程**。P6 整体尚未完成：个人热量、同日多课营养汇总和三餐建议仍待实现。仅本地数据库操作；未提交、推送、部署或操作生产，未修改旧评分规则。

## 实现与边界

- 教练在 Actual lessons 选择课次，查看每人预览并发布已保存版本；未保存改动不能发布，未确认参与或未填实际时长阻止整批发布。
- 参训学员收到自己的活动、实际参与分钟、教练备注和发布时身体资料快照。资料按课次日期选择不晚于该日期的测量；没有资料明确显示缺失，不阻止事实记录发布。
- 缺席者只有缺席记录，没有运动消耗报告。后续将已发布出勤更正为缺席时，最新入口显示更正后的缺席记录，旧记录标记历史版本。
- 学员 `/me/class-reports` 列出每课最新发布记录，详情支持历史版本；不能读取其他学员的数据。新记录独立于旧视频分析报告、任务达标和评分统计。
- 课次版本为幂等发布单位，数据库锁与唯一约束防止并发重复发布；记录和通知在同一事务写入，失败整批回滚，原版本可重试。没有异步分批任务或部分成功状态。
- 新迁移 `20260930_0009` / `20260930_0010` 创建发布/个人记录表及不可修改、不可删除触发器。已发布库禁止破坏性回退；需要前向迁移。未改写旧菜谱快照。
- 营养字段为明确的 `rules_pending`、空热量和空三餐结果；缺席为 `not_applicable`。没有套用成人公式、固定 PAL 或演示热量。

## 用户本轮营养方向

用户确认按“经常运动的人”考虑、主要看热量；三餐分配规则尚无。此确认代表活动背景和展示优先级，尚未确定 4–18 岁公式、强度/时长映射、日常活动与本课消耗去重方式。不能将其直接等同于某个固定 PAL 或 MET 数字。后续 P6b 优先核验热量规则；P6c 再处理全天汇总与经确认的三餐分配。
