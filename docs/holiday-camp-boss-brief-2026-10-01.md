# 假期班训练饮食系统：老板汇报与演示说明

更新：2026-10-01。范围为本次假期班训练饮食模块；不把原有动作视频分析、评分系统或其他页面改版计入本轮新增成果。以下“完成”指本地实现和验证，不代表已部署生产或真实教练验收完成。

## 可以直接讲的 1 分钟版本

我们正在把假期班的训练安排、实际参与情况、课后反馈和饮食参考放进同一套系统。教练记录一次课程，就可以按每个孩子的出勤和实际参与时长生成个人课后报告；家长通过孩子账号查看，减少重复整理和传递记录的工作。

目前训练记录到课后报告的流程已经可以本地演示，菜谱也可以由管理员维护、计算每份营养并发布。饮食部分已能结合孩子的身体资料试算全天热量及三餐热量，教练可以分别选择个人活动情景，保存审核草稿并查看历史。

当前还不是完整的自动饮食推荐产品：单课运动消耗、三餐碳水/蛋白质/脂肪克数，以及正式每日营养建议发布仍未完成。下一阶段需要落实营养规则审核、补完这些功能，再由教练进行真实场景验收后安排上线。

## 已有能力分别解决什么问题

| 模块 | 现在可以做什么 | 对业务的意义 | 当前边界 |
| --- | --- | --- | --- |
| 身体资料 | 保存测量日期、身高体重等及历史 | 能追溯报告采用哪次资料 | 不是当天实时体测 |
| 训练计划 | 教练安排内容，授权学员查看 | 提前沟通训练安排 | 计划不等于实际完成 |
| 实际课次 Actual lessons | 记录实际项目、时长、缺席、提前离场和部分参与 | 能区分孩子真正参与的训练 | 分钟数不等于热量消耗 |
| 个人课后报告 | 教练预览、发布，学员查看自己的记录 | 形成可追溯的个人反馈 | 保存课次后仍需发布 |
| 每日训练汇总 | 汇总同一天各课最新发布的个人分钟数 | 减少多课记录分散、重复统计 | 尚不是每日营养报告 |
| 菜谱 Recipe | 管理员维护食材克数、份数、做法，计算营养并发布 | 建立机构可维护的菜谱内容库 | 演示菜谱不代表首批正式内容已全部准备 |
| 能量审核 | 用本人资料进行候选热量计算、自填三餐比例 | 可以核对输入、结果和规则来源 | 尚无批准的自动三餐规则，未生成宏量营养素克数 |
| 审核草稿历史 | 保存、刷新恢复、查看旧版本、重试去重 | 审核过程可留存，历史不被新资料改写 | 工作人员可见，不发送给学员 |

## 最近几轮新增或修复了什么

1. **修复菜谱验收问题**：角色导航与权限、菜名和食材名称显示、可读的本地演示内容。
2. **新增课后发布流程**：从课次生成个人报告，保留发布快照和修订历史；重复发布不会重复通知。
3. **新增每日训练事实汇总**：同一天多课按最新发布版本统计，缺席及课次日期更正有明确处理。
4. **新增能量工具**：管理员可查能量参考；教练可结合个人资料试算候选全天热量，并输入比例查看三餐热量。
5. **新增审核草稿保存与历史**：保留当时资料、计算结果和来源；刷新恢复、断网重试和并发冲突均有处理。
6. **本轮新增个人活动情景**：班级比较情景之外，可给个别学员选择不同活动类别；每人结果标明采用哪种情景，选择随草稿保存。旧草稿可继续查看。
7. **补充中文操作文档**：解释 Actual lessons、Recipe 编辑、保存/发布区别和审核草稿。

本轮没有改评分规则，没有增加默认三餐比例，没有把审核草稿自动批准为正式饮食建议，也没有操作生产。

## 还差什么，老板需要决定什么

| 剩余工作 | 所需结果 |
| --- | --- |
| 营养规则确认 | 指定审核负责人，确定候选公式适用范围、活动类别判断方法、三大营养素及三餐规则 |
| 单课运动消耗 | 确定运动项目对应的计算规则，接入实际参与时长；处理与全天能量的关系，避免重复计算 |
| 每日营养发布 | 每人每天只有一个明确入口，支持多课、修订、来源追溯和个人权限 |
| 正式菜谱内容 | 确认首批菜品、食材映射、做法、图片及过敏原核对责任 |
| 真实教练验收 | 完整走一遍计划、记录、修改、发布、家长查看流程，确认使用习惯和内容可读性 |
| 上线准备 | 明确目标环境，完成迁移、发布及回退检查；本次尚未执行 |
| 语音/文字辅助 | 确认是否首版必须；当前仍可手动录入，不声称语音功能已完成 |

不建议汇报一个主观“完成百分比”：训练流程与营养规则的完成程度不同，剩余工作也不是等量。当前更准确的里程碑是：**训练流程可本地演示，营养审核可试用，完整每日饮食建议尚待完成。**

## 5–8 分钟演示顺序

本地入口：http://127.0.0.1:3000/auth/login 。后端使用 8000。演示账号见本地验收文档；不要把测试密码放进对外汇报材料。

1. 教练进入 Actual lessons，展示实际时长与个人出勤，解释“计划”和“实际上课”分别保存。
2. 展示课后报告预览/已发布记录；切换学员账号，展示只属于该学员的报告与 Daily summary。
3. 管理员进入 Recipes，展示食材可食用克数、整道菜份数及每份营养；说明 Save draft 与 Publish 的区别。
4. 教练打开 Energy review class (local demo)，查看完整资料、缺资料和缺席情况。
5. 在 Personal energy review 中选班级活动情景，再为 Alex 选择不同的个人情景，重新预览；说明这是审核试算。
6. 保存草稿，刷新后查看恢复的输入与历史；最后明确指出尚未向学员发布正式每日饮食建议。

演示中不要把示例热量作为某个真实孩子的建议，也不要用“系统已经全自动算好饮食”“已上线”概括当前状态。
