# 第二阶段 PRD：战术训练 AI 助手、高光剪辑与长视频分析

最后更新：2026-05-18

## 0. 文档目标

本文档用于整理第二阶段未来几个月的产品需求，覆盖：

- 战术训练 AI 助手
- 2D/3D 战术动画演示
- 固定半场机位下的战术跑位分析
- 指定球员跑位片段剪辑
- 比赛长视频自动剪辑与分析
- 第一阶段模板评分标准调优
- 任务提交、个人中心趋势图、Admin 班级创建流程升级
- Google/微信账号注册、subgroup QR Code 入班、游客模式

本文档只定义产品需求和验收标准，不直接修改当前业务代码。

## 1. 阶段目标概述

第二阶段的核心目标是把 AI Hoops Cloud 从“单人动作模板评分系统”升级为“团队战术训练与比赛视频分析系统”。

第一阶段重点是投篮、运球、基础训练动作的单人视频分析。第二阶段需要增加团队空间、时间点、球员角色、战术模板、长视频事件识别和剪辑能力。系统需要支持教练从战术设计、动画讲解、现场训练录制、AI 复盘，到球员片段剪辑导出的完整闭环。

## 2. 用户角色

| 角色 | 核心诉求 |
| --- | --- |
| Admin | 管理校区、学期、班级、模板、评分规则、用户、系统运营数据 |
| Coach | 创建战术、生成演示动画、录制/上传训练或比赛视频、查看分析报告、导出指定球员剪辑 |
| Student | 查看自己的训练任务、报告、趋势图、战术执行建议和个人高光片段 |
| Guest | 浏览公开功能演示、模板示例和产品能力，但不能上传、保存训练数据或加入班级 |
| Future Parent | 后续可查看学员成长报告和精选视频，本阶段不是主目标 |

## 3. 产品范围

### 3.1 P0 必须完成

- Admin 班级创建流程升级：校区、年份学期、星期、上课时间、时间段班级、subgroup 小班。
- 每个 subgroup 支持独立 QR Code，学生扫码后可自动加入对应班级/小班。
- 注册开放 Google 账号一键注册和微信账号注册。
- 增加游客模式，游客可以浏览功能，但不能进行上传、分析、提交任务等写入操作。
- 第一阶段任务提交链路升级：学员可以显式选择报告提交到任务，不再只自动匹配最近报告。
- 学生分享运球或 training 报告时，可以选择卡通特效遮挡视频中的脸部。
- 个人中心趋势图按类型拆分：投篮、运球、训练，预留战术和比赛趋势。
- 模板评分标准调优框架：评分规则版本化、可审阅、可灰度，不破坏历史报告。
- 战术训练模板数据结构设计：角色、跑位路线、触发点、时间窗、空间容错区。
- 精准 2D 战术动画演示：战术板绘制后可以生成可播放动画。

### 3.2 P1 核心闭环

- 教练通过手动、语音或手绘输入战术指令，生成可编辑战术模板。
- 固定半场机位录制或上传战术训练视频。
- 系统完成半场标定、球员追踪、角色匹配、跑位对齐。
- AI 按标准战术模板输出时间点、空间点、协同点建议。
- 教练可以剪辑指定球员的跑位片段并导出。

### 3.3 P2 增强能力

- 比赛长视频上传或实时录制。
- 教练可以切换锁定比赛球员。
- 自动导出指定球员投篮、传球、跑位等片段。
- 统计投篮次数、传球次数等比赛指标。
- 3D 战术动画实验版本。
- 更复杂的事件识别、评分模型和自动高光集锦。

## 4. 战术训练 AI 助手

### 4.1 业务流程

1. 教练创建或选择一个战术模板。
2. 教练通过语音、手动表单或手绘战术板输入战术指令。
3. 系统把输入转换成结构化战术定义，包括球员角色、起点、路线、目标点、触发条件、节奏要求。
4. 教练在战术板上校正路线和时间点。
5. 系统生成精准 2D 动画演示，3D 动画作为实验能力。
6. 球员根据演示进行半场训练。
7. 教练使用固定半场机位录制或上传视频。
8. AI 对真实跑位和标准战术进行对齐分析。
9. 系统生成报告和建议。
10. 教练按球员导出训练片段或分享给学员。

### 4.2 输入方式

| 输入方式 | P0/P1 要求 | 说明 |
| --- | --- | --- |
| 手动战术板 | P0 | 教练拖拽球员、球、路线、目标点、触发点 |
| 表单输入 | P0 | 用结构化字段描述每个角色的路线、时间、触发条件 |
| 语音输入 | P1 | 语音转文字后生成战术草稿，教练确认后保存 |
| 手绘输入 | P1/P2 | 识别箭头、球员编号、路线，生成可编辑草稿 |

语音和手绘都必须进入“AI 生成草稿，教练确认”的流程，不能直接变成正式评分标准。

### 4.3 2D 动画演示

2D 动画是第二阶段必须实现的功能。要求：

- 使用标准半场坐标系，而不是简单像素位置。
- 支持球员角色编号、球的位置、传球线、跑位线、掩护点、汇合点。
- 支持时间轴播放、暂停、倍速、单步查看。
- 支持触发式战术，例如“1 号跑到 elbow 后，2 号开始 bottom cut”。
- 支持容错区展示，例如目标点周围半个身位范围。
- 支持导出动画快照或短视频，供教练课前讲解。

验收标准：

- 教练绘制一套 3 到 5 名球员的半场战术后，可以生成稳定播放的 2D 动画。
- 动画中的球员路线和战术板坐标一致。
- 每个关键点可以看到目标位置、角色、触发时机和容错区。

### 4.4 3D 动画演示

3D 动画是实验方向，不作为第一版评分依据。

P1/P2 可以尝试：

- 使用同一份战术时间轴生成 3D 场景。
- 提供俯视、侧视、教练视角。
- 展示跑位、传球轨迹和关键空间点。

限制：

- 3D 不参与 P1 评分计算。
- 3D 只作为讲解和展示，不替代 2D 精准战术定义。

## 5. 固定半场机位战术分析

### 5.1 拍摄要求

P1 默认使用固定机位面对半场：

- 摄像机固定，不跟随球员移动。
- 画面覆盖半场关键区域。
- 开始分析前需要完成半场标定。
- 支持录制新视频和上传已有视频。

建议 MVP 阶段允许教练手动标定半场关键点，例如底线角点、罚球线、篮筐中心、三分线关键点。后续再尝试自动标定。

### 5.2 分析维度

#### 时间点分析

系统需要判断：

- 某球员是否过早启动。
- 某球员是否启动太晚。
- 某球员是否在正确的触发点后行动。
- 多名球员之间的时序是否正确。

示例建议：

- “2 号启动早了约 0.8 秒，标准要求是 1 号到达 right elbow 后再启动。”
- “4 号到达掩护点晚了约 1.2 秒，导致 3 号绕掩护时机断开。”

#### 空间点分析

系统需要判断：

- 球员是否跑到目标点。
- 目标点是偏近、偏远、偏左还是偏右。
- 两名球员是否在标准位置汇合。
- 跑位路线是否偏离标准路线。
- 容错区内是否视为完成。

容错建议：

- 默认半个身位以内视为到位。
- 实现时建议转成球场坐标距离，例如 0.35 到 0.5 米，后续按年龄和镜头标定调整。

示例建议：

- “1 号 flare cut 终点偏浅，距离标准三分线外目标点约 0.7 米。”
- “2 号和 5 号汇合点偏右，掩护角度不足，建议 5 号提前站定半步。”

### 5.3 报告结构

战术训练报告至少包含：

- 总体完成度
- 每名球员角色匹配结果
- 每名球员时间评分
- 每名球员空间评分
- 团队协同评分
- 关键失误时间轴
- 路线偏差可视化
- 教练建议
- 可回放视频片段

## 6. 指定球员片段剪辑

### 6.1 训练视频剪辑

教练可以在战术训练报告中选择：

- 指定球员
- 指定战术回合
- 指定事件类型，例如跑位、接球、掩护、投篮
- 片段前后缓冲时间

系统生成剪辑片段并保存为 clip 资产。

P1 至少支持：

- 指定球员跑位片段
- 指定战术回合片段
- 手动调整片段起止时间
- 导出 mp4

### 6.2 未来扩展

后续支持：

- Connor 的所有投篮片段
- Connor 的所有传球片段
- 某球员所有接球后处理片段
- 某球员防守回合片段
- 一键生成训练课高光合集

### 6.3 实时录制与上传分析

第二阶段需要同时支持两种视频来源：

- 上传已有视频文件。
- 在 Coach 端实时录制训练或比赛视频，录制完成后进入同一套分析流程。

P1 的“实时录制”建议定义为浏览器或移动端录制后分片上传，录制结束后触发异步分析。真正低延迟的边录边分析可以放到 P2/P3，不作为第一版闭环的硬要求。

## 7. 比赛长视频自动剪辑与分析

### 7.1 业务目标

教练可以上传比赛长视频，或在比赛中实时录制。系统帮助教练围绕指定球员进行检索、剪辑和统计。

### 7.2 核心功能

- 创建比赛视频分析任务。
- 录入或导入比赛球员名单。
- 教练可以在视频中锁定某名球员。
- 支持切换锁定球员。
- 自动识别并导出该球员相关片段。
- 支持投篮计数、传球计数等基础指标。
- 支持按球员、事件类型、时间段筛选。

### 7.3 MVP 事件类型

| 事件 | P1/P2 优先级 | 说明 |
| --- | --- | --- |
| shot_attempt | P2 | 投篮尝试 |
| made_shot | P2 | 命中可先依赖人工标注或比分板后续识别 |
| pass | P2 | 传球事件，MVP 可先人工校正 |
| catch | P2 | 接球 |
| drive | P2 | 持球突破 |
| off_ball_cut | P2 | 无球跑位 |
| rebound | P3 | 篮板 |
| defensive_possession | P3 | 防守回合 |

MVP 允许 AI 初筛，教练人工修正。不要把第一版目标定为完全自动、零校正。

## 8. 第一阶段模板评分标准调优

### 8.1 当前问题

第一阶段已有投篮、运球、训练模板，但评分标准和计分方式仍需优化。当前本地模板 JSON 和 `web/src/lib` 计算逻辑是核心资产，不能随意改动。

### 8.2 产品要求

- 模板必须有版本。
- 每次报告必须记录使用的模板版本。
- 评分规则修改后，不应改变历史报告的解释。
- Admin 可以查看评分规则摘要。
- 后续支持规则草稿、dry-run、发布、归档。
- 支持按年龄、level、训练目标调整阈值。

### 8.3 调优流程

1. Admin 或技术人员创建评分规则草稿。
2. 系统用历史样本 dry-run，对比新旧评分差异。
3. 教练或专家审核差异。
4. 发布新版本。
5. 新报告使用新版本，旧报告保留旧版本。

## 9. 任务提交链路升级

### 9.1 当前问题

第一阶段 task 不一定只是“提交报告”。当前已经有用最近匹配报告提交任务的能力，但还缺少用户显式选择报告提交。

### 9.2 产品要求

任务需要支持多种提交方式：

- 上传新视频并分析
- 选择已有报告提交
- 教练线下确认
- 手动填写训练完成记录
- 未来提交战术训练回合或比赛片段

P0 需要完成：

- 学员在任务详情中看到可提交报告列表。
- 学员手动选择某个报告提交。
- 系统校验报告归属、模板、类型、班级上下文。
- 一个报告是否允许提交多个任务，需要由任务规则配置控制。

## 10. 训练报告分享与隐私保护

该需求只适用于普通训练报告分享，即运球页面和 training 页面的视频生成报告，不包含战术训练报告。

产品要求：

- 学生分享运球或 training 报告时，可以选择开启卡通脸部遮挡。
- 卡通特效只作用于分享版本或导出的分享视频，不修改原始上传视频。
- 分享前需要提供预览，让学生确认遮挡效果。
- 如果人脸识别置信度低，系统需要提示重新生成、手动调整或仅分享无视频报告。
- 管理端和教练端查看原始报告时仍按权限访问原始内容，不自动套用分享特效。
- 该能力需要在内测/公测前完成，优先保护未成年人和学员隐私。

## 11. 个人中心趋势图升级

### 11.1 当前问题

当前趋势图把所有报告评分混在一张图中，不利于区分投篮、运球、训练。

### 11.2 产品要求

个人中心趋势图需要按分析类型拆分：

- 投篮趋势
- 运球趋势
- 训练趋势
- 后续预留战术训练趋势
- 后续预留比赛表现趋势

每个趋势图至少支持：

- 最近 7 天
- 最近 30 天
- 最近 90 天
- 总体平均分
- 最佳分
- 训练次数
- 最近一次报告入口

## 12. Admin 班级创建流程升级

### 12.1 当前目标

Admin 创建班级不应只是填写一个 class。新的结构需要表达真实运营逻辑：

校区 -> 年份学期 -> 星期几 -> 当天时间段 -> 时间段下不同小班。

### 12.2 关键概念

| 概念 | 说明 |
| --- | --- |
| Campus | 校区，例如 City Campus、North Campus |
| Academic Term | 年份学期，例如 2026 Term 1、2026 Term 2、Holiday Term 1 |
| Class | 一个固定上课时间段，例如周一 16:00-19:00 |
| Subgroup | 同一时间段里的小班，例如 U10 Beginner、U14 Advanced |

### 12.3 创建流程

1. 选择校区。
2. 选择年份和学期。
3. 选择星期几上课，支持周一到周日多选。
4. 选择当天上课时间，例如 16:00-19:00。
5. 创建该时间段下的小班 subgroup。
6. subgroup 可按年龄、level、教练、容量区分。
7. 系统自动生成 class title。
8. Admin 可编辑 description。

自动 title 示例：

- `City Campus 2026 Term 1 Monday 16:00-19:00`
- `North Campus 2026 Holiday Term 1 Tue/Thu 09:00-12:00`

subgroup title 示例：

- `U10 Beginner`
- `U12 Intermediate`
- `U16 Advanced`

### 12.4 兼容要求

当前系统已有 `training_camps`、`camp_classes`、`class_members`。第二阶段不建议立刻推倒重命名。建议短期把 `camp_classes` 语义升级为“时间段班级”，新增 `class_subgroups` 表表达小班。

### 12.5 Subgroup QR Code 入班

每个 subgroup 需要有自己的 QR Code。学生扫码后可以进入注册/登录/加入流程，系统自动把学生加入对应 class 和 subgroup，减少 Admin 逐个分配的成本。

产品要求：

- 每个 subgroup 可以生成独立 QR Code 和 invite link。
- QR Code 对应的是 subgroup，不只是 class。
- 未登录用户扫码后进入注册或登录流程，完成后继续加入 subgroup。
- 已登录 Student 扫码后可以自动加入，或根据 subgroup 配置进入待审核状态。
- Admin 仍然保留手动分配学生到 class/subgroup 的权限。
- Admin 可以禁用、重新生成、设置过期时间、查看扫码加入记录。
- 系统需要防止重复加入同一个 subgroup。
- 如果 subgroup 已满，需要提示容量已满，并进入待处理或拒绝加入。

建议入班模式：

| 模式 | 说明 |
| --- | --- |
| auto_join | 扫码后直接加入 subgroup |
| approval_required | 扫码后创建申请，Admin 或 Coach 审核后加入 |
| disabled | QR Code 暂停使用 |

P0 可以先支持 `auto_join` 和 `disabled`，P1 再补 `approval_required`。

## 13. 注册与访问模式

### 13.1 Google 账号一键注册

系统需要支持 Google 账号一键注册和登录。

要求：

- 新用户可以使用 Google 账号创建 Student 账号。
- 老用户可以绑定 Google 身份，后续用 Google 登录。
- 如果 Google email 与现有账号 email 一致，需要提供安全的账号绑定流程。
- Google 注册后的默认角色为 Student，Admin 可以后续调整角色或分配班级。

### 13.2 微信账号注册

系统需要支持微信账号注册和登录。

要求：

- 新用户可以使用微信创建 Student 账号。
- 老用户可以绑定微信身份，后续用微信登录。
- 需要保存微信 provider identity，例如 openid/unionid，避免重复创建账号。
- 微信注册后的默认角色为 Student。
- 如果微信网页应用、公众号、小程序的接入形态不同，架构上需要保留 provider metadata。

### 13.3 游客模式

游客模式用于降低体验门槛，让潜在用户可以浏览系统能力。

游客可以：

- 浏览公开功能介绍。
- 浏览公开模板列表和演示内容。
- 查看样例报告。
- 体验不保存数据的前端演示流程。

游客不可以：

- 上传视频。
- 创建训练 session。
- 生成真实 AI 报告。
- 提交任务。
- 加入班级或 subgroup。

## 15. 主要风险

- 球员多人遮挡导致追踪不稳定。
- 球员身份识别困难，尤其无球衣号码或画质较差时。
- 固定机位不标准会影响半场标定精度。
- 战术模板如果没有结构化 DSL，后续评分会失控。
- 长视频事件识别复杂度高，第一版应允许人工修正。
- 评分标准频繁变动会影响历史报告一致性，必须版本化。
- Google/微信注册如果没有账号绑定策略，容易产生重复账号。
- QR Code 如果长期有效且无审核，可能被非目标学生误扫加入。
- 游客模式如果权限边界不清晰，可能意外开放上传或私有数据访问。
- 卡通脸部遮挡如果识别不稳定，可能影响学生隐私保护，需要预览和低置信度提示。

## 16. 待确认问题

- Holiday term 是否固定为 `Holiday Term 1` 和 `Holiday Term 2`，还是每年按运营自定义？
- 战术训练 P1 是否只覆盖半场 3v3/4v4/5v5，还是也覆盖个人战术脚步？
- 固定机位是否有推荐设备、推荐高度和推荐角度？
- 战术分析第一版是否要求识别球，还是先以球员跑位为主？
- 比赛长视频第一版是否必须自动识别投篮命中，还是只做 shot attempt 和人工修正？
- 训练剪辑导出是否需要直接分享给学员，还是先只供教练下载？
- subgroup QR Code 第一版是否直接自动加入，还是部分校区需要 Admin/Coach 审核？
- 微信注册优先接入网页扫码登录、公众号登录，还是未来小程序登录？
- Google/微信账号是否必须补手机号，才能加入正式班级？
