# P5b：食品检索、菜谱版本与营养换算后端

本批完成后端 API 和持久化，未实现 Admin 菜谱编辑 UI 或独立菜谱浏览页面。未进行生产迁移、部署或真实教练 UAT。下一批 P5c 接入这些页面及桌面/手机导航，不把 P5 整体标为完成。

## 已实现

- 所有食品/菜谱接口要求登录。Admin 维护草稿及发布；Coach / Student 可检索食品、读取已发布菜谱和历史版本。前端继续按姓名展示学员，本批不涉及账号或学员界面。
- 食品按明确 release_id 查询名称，支持分页；名称原文、食品描述和来源一起返回，生熟食品条目不自动替换，搜索中的 `%` / `_` 按字面字符处理。
- 菜谱保存标题、图片 URL（可选）、做法、份数、成品重量（可选）、匹配状态食材可食用克数、过敏原和饮食说明。过敏原记录有独立 reviewed 标记，未审核不代表无过敏原，不从营养数值推断。
- 创建使用请求 UUID 去重；草稿修改有版本冲突保护及相同请求重试识别。发布同版本幂等，并发只产生一个发布快照。
- 修改草稿不会替换现有发布版；发布新版后，旧版本仍能按 version 查询。快照保留食材原文、营养数值、来源版本/fingerprint/文件校验值、估算结果和计算版本。
- 份量预览只读取发布快照，不保存实际摄入记录，也不改变菜谱。默认一份，可查询小数份数。

## 营养口径

使用 `recipe-composition-v1`：每 100g 选定食品营养 × 匹配状态可食用克数 / 100，先精确汇总后以 Decimal half-up 保留两位输出。总量 / 份数得到每份；有成品重量才提供成品每 100g 和每份重量。

能量来自含纤维 AFCD 能量字段，kcal = kJ / 4.184；不以 4/4/9 覆写。计算只取绝对营养字段，不对 `%T` 或 `mg/gN` 求食物总量。不推断烹调保留率、失水、弃油、吸油，也不生成个体营养处方。

任一食材某营养素缺值，该项总量/每份/成品每 100g 为 null；仍返回已知小计及缺失食材索引。零值保持有效。未来新增计算版本不得修改 v1 历史份量预览的算法。

## 接口交接（前缀 `/api/v1`）

| 方法与路径 | 用途 |
| --- | --- |
| GET `/foods/releases` | 来源列表 |
| GET `/foods?release_id=...&query=...&limit=20&offset=0` | 食品检索 |
| GET / POST `/admin/recipes` | 草稿列表 / 新建 |
| GET / PUT `/admin/recipes/{id}` | 读取 / 修改草稿 |
| POST `/admin/recipes/{id}/publish` | 发布 expected_version |
| GET `/recipes` | 每个菜谱的最新已发布版本列表 |
| GET `/recipes/{id}?version=1&servings=1.5` | 已发布详情 / 份量预览 |
| GET `/recipes/{id}/versions` | 发布历史，支持 limit/offset |

请求字段与边界以 `server/app/schemas/recipe.py` 和 OpenAPI 为准。读写草稿使用同一 recipe id；publication_id 单独标识发布快照。API 当前不提供删除或撤回，Admin 页面后续不能虚构这些操作。
