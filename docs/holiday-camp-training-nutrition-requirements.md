首读入口：[本轮开发交接](holiday-camp-development-handoff-2026-10-03.md)。实施与验收：[开发计划](holiday-camp-development-plan.md)。计算与数据口径：[课程消耗与 AFCD 规范](holiday-camp-nutrition-spec.md)。页面组织：[个人中心方案](personal-center-development-plan.md)。

## 1. 已确认的精简范围

家长端由三个核心模块组成：**个人 Profile → 今日训练 → 食材营养参考**。重点是少填写、容易查看；训练数据由教练记录。家长继续代管球员账号，不新增独立家长角色或多孩子关联体系。

| 模块 | 展示与输入 | 本轮边界 |
| --- | --- | --- |
| Profile | 姓名/昵称、出生日期、性别、身高、体重、测量日期、开始训练日期；年龄、BMI、训练年限自动计算 | 复用现有资料及测量历史，不扩展体测量表或能力评分 |
| 今日训练 | 今日实际训练项目、个人参与分钟、强度、教练反馈、课程及当日估算消耗 | 教练录入和发布；家长查看本人已发布记录 |
| 食材营养 | 肉、蛋、奶、常见蔬菜的每 100g 碳水、蛋白质、脂肪 | 使用 AFCD 数据，简单分类/搜索，不生成菜谱或配餐 |

现有训练计划、任务、动作评估报告及其评分规则继续保留；新增课程报告和估算结果不混入旧视频评分统计。桌面/手机现有个人中心结构继续复用。

以下内容不再属于本轮交付：全天能量需求试算、三餐配额/比例/宏量营养素目标、菜谱推荐和菜谱维护扩展、自动餐单、实际饮食打卡、热量缺口、详细身体能力评分、心率/手表设备接入、语音/AI 辅助录入及向邮件/外部聊天渠道自动发送报告。

## 2. Profile 的最少录入

- 复用已有账号姓名/昵称、出生日期与性别；联系方式仍按原账号流程处理，不另建重复表单。
- 体测继续录入身高 cm、体重 kg、测量日期，保留历史记录；BMI 由对应条目的 `weight_kg / (height_cm / 100)^2` 计算，不要求用户录入 BMI。
- 用户已明确“训练时间”仅指**开始训练日期/年限**。新增可空 `training_started_on`，属于个人基础资料，不属于每次体测；训练年限展示为年/月，不持久化随时间失真的 `training_years`。
- 年龄按出生日期计算；课程计算用上课日期的年龄，Profile 展示用当前 Sydney 日期的年龄。开始训练日期不可晚于当前日期或早于出生日期；旧账号未填写时显示“未填写”，不默认为 0 年。
- 资料可按需更新，日常查看课程和食材不要求重复录入。新增基础资料写入复用本人权限；不因本轮改造新增教练代填体测权限。
- BMI 首版只显示数值，不套成人肥胖/减重分类；不增加体脂、肌肉量、心率、柔韧性、力量、协调、耐力等表单、综合分数或自动成长百分比。已有测量历史用于追溯，趋势图不是本轮必要项。

## 3. 教练记录与家长查看

教练从现有计划创建课次 → 录入实际训练项目/分钟和简单强度 → 确认个人出勤/参与差异 → 预览训练内容和估算结果 → 发布 → 家长在软件内查看本人课程及今日汇总 → 按需查看食材营养。

项目使用常用活动预设，关联后台有来源的活动代码；允许补充显示名称或备注。教练不手填 MET/METy、营养数字或三餐比例。不要求每节课新增一整套体测。

- 每项实际时长与每人参与时长沿用已有课次模型。计划时长不是实际时长；缺席、早退、部分参与不得按全班分钟计算。
- 同一课的训练、讲解和休息应按实际项目区分，不把整堂课都当连续高强度活动；未知时长不能默认为全勤或零消耗。
- 家长页面只读取已发布的个人快照，不展示全班名单或其他学员资料。草稿和未确认课次不计入今日结果。
- 现有课后发布/修订/通知流程作为唯一发布链路；不新增独立每日营养审批系统，不自动发送外部消息。

## 4. 课程消耗的已确认选择策略

1. 有适龄儿童专用参考时优先使用；首选已核验的 NCCOR Youth Compendium smoothed METy，覆盖 6–9、10–12、13–15、16–18 岁。计算采用 `METy × 基础代谢(kcal/min) × 本人实际参与分钟`，逐项目汇总。
2. 已有儿童条目中的项目/强度信息通过活动映射选取，不再统一追加此前示例的 `0.8 / 1.0 / 1.15` 系数；METy 不可直接代入固定 `3.5` 的标准 MET 公式。
3. 无精确对应项目时，优先采用有记录的相近儿童活动并标为“类比估算”。4–5 岁不能直接套用 6–9 岁年龄表；优先核查适龄研究条目，再进入用户允许的粗略估算分支。
4. 仍无适龄参考时，可按已说明适用性限制的通用近似规则估算；先准备可追溯的活动基准及映射，不猜 MET、儿童系数或误差范围。通用分支的公式、强度参数和完整兜底策略见营养规范。
5. 所有输出均为估算，家长显示“课程期间估算热量 ≈ … kcal”；不称精确实测、净活动热量或全天能量需求，不把消耗自动转换成必须补吃的热量。
6. 必要输入或映射仍缺失时显示“暂无法估算”；部分项目可算时显示“已估算小计/尚有项目未估算”，不把未知当 0。训练事实仍可发布和查看。

用户已经确认上述选择策略；本轮已准备 9 个活动映射、核对来源并保存版本快照，不再把旧三餐规则审批作为本轮前置条件。儿童参考及通用估算本身都不是个体实测。

来源：[NCCOR 使用方法](https://www.nccor.org/tools-youthcompendium/how-to-use/) · [NCCOR FAQ](https://www.nccor.org/tools-youthcompendium/faqs/)。完整计算边界与测试案例见 [计算规范](holiday-camp-nutrition-spec.md)。

## 5. 食材营养的明确边界

- 独立“食材营养”入口，分类为肉、蛋、奶、蔬菜；首批精选数量为实施建议，约 20–30 种，不是新增业务硬指标。
- 每条展示易懂名称、食品状态及 **每 100g 可食部分**的碳水/蛋白质/脂肪 g；来源采用固定且可追溯的 AFCD 版本。
- 生/熟、部位、奶品脂肪类型等不同条目须准确匹配；鸡蛋按去壳可食部分，牛奶按 100g，不自行当作 100ml。
- 缺失值保持未知，不当 0；食品原始名称/键及来源保持不变，中文名称和分类采用独立轻量映射。
- 家长按信息自行选择食材；不提供菜品做法、整餐组合、个人食用克数或三餐处方。首版不要求复杂食材后台，版本化精选配置即可。

来源：[AFCD 官方说明](https://www.foodstandards.gov.au/science-data/food-nutrient-databases/afcd/about-afcd)。

## 6. 现有基础与本轮修改

2026-10-03 改造前已具备体测录入/历史、实际课次/个人分钟、课后发布快照、每日训练事实汇总、AFCD 导入和食材读取接口。原 `personal_energy_service.py` 计算全天能量需求候选，原快照 `nutrition` 没有课程消耗；本轮使用独立 `exercise_energy_service.py` 和冻结的 `exercise_energy` 字段实现课程估算。

本轮已实现基础资料的开始训练日期读写、BMI 展示、活动预设映射、独立课程消耗服务、报告结果快照及每日汇总、家长端三模块和独立食材营养页。本地库备份后已升级至 0012，官方 AFCD 1,588 条已导入，28 条精选可读；后端 163、前端 206 测试及类型/构建检查通过。数据库、自动化、本地浏览器、真实用户确认与正式部署仍分别记录。

旧菜谱、全天需求和审核草稿服务退出主流程，但保留原数据、已有发布快照及历史验证文档，不删除相关表、不重算旧报告。旧报告缺新增字段时显示历史版本/未估算，不静默补算。

## 7. 本轮完成标准

- 少量资料可保存并恢复，年龄/BMI/训练年限自动显示；旧测量记录可读。
- 教练记录、预览、发布，家长查看本人训练内容和估算消耗的流程真实可用；缺席/部分参与、未知输入和权限正确。
- 同日多课按每课最新发布版本汇总，重复发布/重试不重复统计；课程移日或修订有清楚结果。
- 食材按 AFCD 对应条目可复算每 100g 三大营养素，名称可读，生熟/单位/缺失正确。
- 旧视频评分、任务提交、报告历史和账户角色回归通过；旧公式/体重/食品更新不改写旧发布快照。
- 代码、迁移、自动化检查、浏览器流程、真实教练/家长 UAT 和部署分别记录证据；当前已完成本地实现和合成账号联调，用户本人确认与部署待执行，批次详见开发计划。

# 假期班首版：训练、三餐营养与个人中心需求

更新：2026-09-27。状态：需求整理完成；新功能尚未实施或验收。

执行入口：[开发交接](./holiday-camp-development-handoff-2026-09-27.md)。排期及验收：[开发计划](./holiday-camp-development-plan.md)。营养口径：[营养与 AFCD 规范](./holiday-camp-nutrition-spec.md)。UI：[个人中心方案](./personal-center-development-plan.md)。

## 1. 用户已确认的范围

- 在现有 AI Hoops 系统内开发；学员为 4–18 岁，家长直接代管球员账号，不建独立家长账号。
- 手机号或邮箱至少提供一个；不扩展同一家长多孩子管理。现有手机号必填约束需核对，支持邮箱单独注册需前后端和迁移一致。
- 假期班首版同时包含：个人中心桌面/手机改版、训练计划、教练课次记录、个人课后报告、全天三餐营养建议、独立菜谱页面及基础内容维护。
- 周期体测、体测批量导入、体测视频成长档案暂不做。
- 不记录实际饮食，不做饮食打卡、实际摄入追踪或实际热量缺口。
- 教练是训练记录主要输入者：记录班级运动项目、实际时长，并记录个人缺席、提前离场和部分参与情况。
- 课后报告在软件内生成，球员账号查看；不依赖邮件交付。
- 饮食建议明确到早餐、午餐、晚餐的碳水、蛋白质和脂肪克数/参考范围。
- 菜谱是独立页面，用户能浏览每道菜、食材和营养成分及含量；采用 AFCD 食品营养数据。
- 个人中心拆分历史记录、任务提交、趋势等独立页面。桌面顶部保留 Shooting / Dribbling / Training，个人中心在右上角；桌面左侧页面导航、右侧内容。
- 手机右上角个人中心与菜单，菜单包含桌面页面导航。已接受的设计方向为顶栏下方一行 Shooting / Dribbling / Training；详见 UI 方案。

## 2. 业务流程

教练制定并发布计划 → 球员查看 → 教练从计划创建课次 → 更新实际项目、时长和参与名单 → 确认发布 → 为参训球员生成课后报告 → 汇总当天已记录课程，生成同一天的三餐建议 → 用户按需浏览菜谱。

计划和实际记录分开保存。计划时长不代表实际参与时长，动作次数不直接等于精确热量。全班共享课次项目，每名球员保存个人参与覆盖项。缺席者保留缺席记录，不生成该课运动消耗报告；未确认状态不能默认为全勤。

## 3. 角色职责与报告

| 角色 | 主要操作 |
| --- | --- |
| Admin/内容维护人员 | 维护食品映射、菜谱、规则版本和基础资料；监督发布 |
| Coach | 仅管理授权班级；制定计划、记录课程和个人差异、预览并发布 |
| 球员账号（含家长代管） | 查看自己的计划、任务、报告、趋势和饮食建议；浏览菜谱 |

课后报告包括：课次/班级/日期、实际训练内容与参与时长、使用的身体资料及测量日期、运动消耗估算、当天三餐营养参考、来源和估算说明。它不是一次新的体测，不声称测得当天身体状态。

同日多课共享一个当天营养建议入口；修订课程后生成建议修订版本，避免用户把多份全天建议相加。晚上生成的全天参考不代表晚餐还需补吃全天量。

## 4. 建议采用的实现边界

- 首版训练目标使用“基础体能、动作与协调、篮球专项表现、综合发展”，作为教练训练重点，不做增肌/减脂热量开关。名称为当前设计默认值，可调整文案。
- 先完成结构化表单，再接文字/语音转写及 AI 整理；AI 输出需教练确认，不自动编造项目、时长、参与名单或营养数字。语音首版优先级和服务商未最终确定，不能静默删减，也不能成为手动录入的依赖。
- 训练计划支持班级分配及个人调整、日期、动作、组次/次数/时长、说明，可关联已有评分模板；普通篮球项目不要求必须存在视频分析模板。
- 新课次、参与记录、营养报告独立建模；不改变旧视频分析 session、评分 report、任务提交及增长统计的含义。
- 发布保存输入与规则快照，重复发布/网络重试不重复创建报告或通知。已发布内容更正留修订记录。
- 菜谱首版由机构维护，不做用户上传饮食照片识别，不做自动处方或自动长期计划。

## 5. 尚需落实的产品/内容决策

1. 4–18 岁各年龄适用的能量估算、运动估算、三大营养素目标及三餐分配规则；由谁审核和何时交付。
2. 首批菜谱及食物条目清单、图片和做法来源；数据许可与署名方式须在导入时核对。
3. 语音输入是否为假期班首版硬性门槛；服务商、语言和音频保留策略。

以上未知项只阻塞依赖它们的实现/发布，不阻塞导航拆分、班级计划和手动课次记录。
